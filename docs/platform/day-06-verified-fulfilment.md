| Work package           | Result                                                                                                                                                                                                                                                                                                                     |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Webhook verification   | Verifies the raw HMAC before parsing, checks the saved order and gets current payment evidence from Razorpay Test Mode. It checks the payment ID, order ID, amount in paise, INR, capture flag, payment status and refunds.                                                                                                |
| Atomic fulfilment      | Locks the invitation and its bound test order. The unique verified order remains the entitlement. Captured state, provider identifier, verification source, and the webhook outcome commit together. Provider event ID and raw-body digest protect against duplicate processing.                                           |
| Authorized publication | Retains verified-session, owner, canonical Zod, optimistic version and unique slug checks. The transaction verifies the Afterglow order binding and requires an owned, normalized cover or no cover. A repeated request returns the original slug.                                                                         |
| Guest projection       | The database allowlists nested guest content for both published read paths. The canonical schema validates that projection again before rendering. Gallery references and raw cover URLs stay private. A published cover is delivered through the existing no-store slug route. Revocation and deletion stop future reads. |
| Recovery               | A returning owner can reconcile via the existing status URL without a browser callback or webhook. A database lease permits one provider read per unresolved order per 15 seconds. Verification reads time out after 4.5 seconds. Failed reads preserve the saved state.                                                   |
| Frontend integration   | The existing checkout, publish review, copy link, WhatsApp handoff and public guest renderer consume the same route and response contracts. A cover rejection returns a 422 with an instruction to use an owned upload or remove the cover.                                                                                |

Permanent mismatches and unrelated signed events with no order ID are durably recorded as ignored. The webhook returns 204 only after this outcome or a prior committed duplicate is known. Invalid signatures return 401. Provider errors, unattached order IDs, lagging capture and transaction errors return 503 for retry. Newly verified receipts record whether fulfilment came from a webhook or an authenticated owner check. Existing verified receipts retain their original evidence. A late failed event cannot change a verified receipt. Payment leaves the draft editable and private until the owner publishes.

## Migration and recovery

Apply 20261124120000_verified_test_fulfilment.sql and 20261124120100_guest_invitation_projection.sql in order to an authorized staging database before deploying the updated app. Check migration history and take a recoverable database backup first. The first migration changes the fulfilment RPC signature by adding an optional digest argument, so existing positional calls remain valid. The second replaces the public projections and staging publication RPC without widening client access. No existing migration is rewritten.

For an incident, disable staging publication while investigating and leave unresolved orders available for reconciliation. Preserve verified orders, event records and share slugs. Use a reviewed forward migration for a database rollback. Rolling back only the application to the previous webhook handler would restore the signed-payload-only behavior, so keep the staging webhook disabled until the verified handler is restored. Re-enable the endpoint and use Razorpay's Test Mode webhook retry UI for any outstanding events.

If a customer returns before the webhook arrives, open the existing checkout page and use **Check payment status**. If the provider lookup is temporarily unavailable, wait for the 15-second lease and retry. For persistent mismatches, compare the Test Mode dashboard capture and amount with the saved order using authorized operator access. Do not mark the order verified manually, generate a second order or grant publication based on a customer screenshot.

## Reviewer acceptance on staging

1. Configure authorized staging Supabase, private R2, HTTPS SITE_URL and matching Razorpay Test Mode keys. Use a dedicated webhook signing secret different from the API secret. Configure the three supported events payment.captured, payment.failed and order.paid. Keep staging publishing disabled on production.
2. Pick Afterglow, sign in as a test user, create and save a fictional draft, reload it and open the watermarked preview. If using a cover, upload a test photo through Studio.
3. Open Test Mode checkout and complete a sandbox capture. Verify the status reports a server-verified receipt. Return in a new browser after closing checkout and confirm recovery. Resend the actual webhook through the provider dashboard and confirm the same fulfilment. Test cancelled and failed attempts on another draft and confirm publication is denied.
4. Use the owner publish review, confirm a slug, copy the returned link and inspect the WhatsApp destination without sending anything. Open the link in a fresh guest context and check the photo, ceremony, directions and absence of a watermark. The original draft and its private image path should deny a second account and an anonymous guest.
5. Check that repeated publication retains the same link, an unpaid draft remains private, and a cancelled or mismatched payment has no entitlement. Record the hosted checkout, webhook receipt and guest outcome with redacted evidence.
